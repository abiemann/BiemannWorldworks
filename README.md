# Biemann Worldworks

The public [Biemann Worldworks website](https://abiemann.github.io/BiemannWorldworks/) introduces Velvet Sky for Meta Quest with in-app screenshots and a 30-second trailer. The [Velvet Sky privacy policy](https://abiemann.github.io/BiemannWorldworks/privacy/) covers the app, support correspondence and this website.

The November 13, 2026 policy update matches the current A-button menu: observing places come from Cities, manual GPS or a QR scan, with no headset device-location request. It describes the locally stored place name, coordinates, time zone and preferences, optional local-only camera scanning, and deletion through the headset's app-data controls or uninstall. It retains the confirmed support/deletion contact, GitHub hosting disclosure and separate optional is.gd statistics disclosure. The policy URL above is the address to enter in Meta's Privacy Policy field; GitHub Pages publishes the revision from the main branch.

The owner confirmed a **Mixed Ages** intended audience, including children aged 10–12 and teens/adults. The policy describes this 10+ audience and parent/guardian help for the optional website and support contact. This wording does not implement Meta's age-category checks or parental-consent features. Dashboard age-group self-certification, the IARC questionnaire, and the required mixed-age Get Age Category API integration with its applicable Data Use Checkup and platform setup are still pending. Review the policy again when that SDK processing is implemented. See [Meta's mixed-age requirements](https://developers.meta.com/vr/documentation/spatial-sdk/ps-requirements/) and [age-group guidance](https://developers.meta.com/vr/resources/age-groups/).

GitHub Pages serves the static site from the root of the main branch. To preview locally, serve this directory with any static HTTP server and open the home page. Use the links in the page footer to review the privacy policy and sky imagery credits.

The company browser icon is a black capital B on an opaque white square. The original vector is `favicon.svg`, with 16/32/48-pixel ICO fallbacks, a 32-pixel PNG and a 180-pixel Apple touch icon. All three pages use repository-relative links so the icon works under the GitHub Pages project path.

## Location QR generator

Use the memorable [is.gd/vtsky](https://is.gd/vtsky) shortcut, or the direct [abiemann.github.io/BiemannWorldworks/gps/](https://abiemann.github.io/BiemannWorldworks/gps/) address. Name the place, press **Use my location** and grant permission, or enter signed decimal coordinates manually. Desktop browsers may give coarse estimates; reported accuracy is displayed. Choose **Time zone at this place** before generating: it starts with the device's zone, so correct it when entering a location elsewhere. Press **Generate QR code** and scan the result in Velvet Sky's **A → Location → Enter GPS → Scan QR**. Scanning fills the form, including its local time zone, for review; **Save** applies it. A phone and laptop both work, and optical scanning needs no shared Wi-Fi network.

The free is.gd shortcut redirects directly to the generator, with detailed statistics enabled. Its [public redirect statistics](https://is.gd/stats.php?url=vtsky) count accesses to this shortcut, not all website visits or unique people; automated requests and repeat visits can be included. is.gd may report browser, country and referring-page information, and keeps IP information for abuse prevention under [its privacy policy](https://is.gd/privacy.php). No place name or coordinates appear in the shortcut. Its target cannot be changed later, so retain the stable GitHub route and direct link as a fallback. The older [is.gd/velvetsky](https://is.gd/velvetsky) alias still works with its original detailed statistics off.

QR generation runs locally using the bundled [Nayuki library and license](gps/vendor/NOTICE.txt). Names/coordinates are not uploaded, added to URLs, or saved by the page. Downloading explicitly creates a location-bearing PNG. Anyone with the QR can read its location.

To check statistics, bookmark [https://is.gd/stats.php?url=vtsky](https://is.gd/stats.php?url=vtsky). **No account, username or password is needed.** The report is public and free to view.

Version 1 payload is plain text: `DV=1&LAT=47.6062095&LON=-122.3320708&Name=Seattle+balcony&TZ=America%2FLos_Angeles`. New codes have five case-sensitive fields and include a region time-zone identifier, preserving local daylight-saving rules. Names and values use UTF-8 form encoding. Only finite in-range coordinates, trimmed single-line names of 1–64 UTF-16 characters and supported IANA zone identifiers are accepted, matching the updated app. The app also accepts old four-field codes and asks the user to confirm their missing time zone before saving. The generator clears a stale code whenever its inputs, including time zone, change. Geolocation is requested only from the button, times out after 15 seconds and offers retry/manual entry on errors.

## Publishing

The website has no added page-visit counter. The app itself remains offline and has no analytics service. Deployment requires committing/pushing this repository's changes to main; changes in the VelvetSky app repository do not publish this website.

## Checks

Run `node --test tests/location.test.cjs`. Ten tests execute the shipped event handlers with unit DOM doubles and the real bundled QR encoder. They cover five legacy fixtures and five shared time-zone fixtures, zone selection/validation and stale-code clearing, geolocation success and reported accuracy, denied/unavailable/timed-out fixes and retry, insecure/unsupported browsers, editing while a fix is pending, invalid fields and PNG download data. A fallback-form check ensures no named controls can place input values into a native GET URL if scripts fail. These tests use synthetic fixes; they do not claim a real phone GPS fix or browser permission trial. A new local browser check verifies selection of Pacific/Auckland and America/Los_Angeles, their exact TZ payloads, stale-code clearing and a 320-pixel layout without horizontal overflow. Prior actual canvas PNGs decoded to the exact expected four-field payload with ZXing, and the Quest camera read the original public Seattle fixture; the new time-zone payload still needs its optical/device check. Full physical device/browser acceptance is separate from these checks.
